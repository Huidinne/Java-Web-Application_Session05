# Phân tích luồng dữ liệu – Bài 3

Khi người dùng nhấn vào nút "Chỉnh sửa" ở trang danh sách món ăn (View A), hệ thống sẽ gửi request đến đường dẫn dạng `/bai3/edit/{id}`.

Controller (`AdminDishController`) sẽ nhận ID từ URL, sau đó gọi `AdminDishService` để tìm món ăn tương ứng. Nếu tìm thấy, Controller sẽ đưa đối tượng `Dish` vào Model và trả về trang `edit-dish.html`.

Ở View B (trang chỉnh sửa), Thymeleaf sử dụng `th:object` để nhận đối tượng món ăn và dùng `th:field` để tự động đổ dữ liệu vào các ô input như tên, giá, trạng thái.

Nếu ID không tồn tại, Controller sẽ không hiển thị trang chỉnh sửa mà chuyển hướng về `/bai2/dishes` và gửi kèm thông báo lỗi: "Không tìm thấy món ăn yêu cầu!".

Tóm lại, dữ liệu đi theo luồng:
View A → Controller → Service → Model → View B.

Các biểu thức Thymeleaf sử dụng gồm:

* `th:object` để binding object
* `th:field` để binding dữ liệu vào input
* `@{...}` để tạo đường dẫn động có chứa ID
